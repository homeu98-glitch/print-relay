### 問題一：header 印 "null"
根因鏈（四步全部實證）：
1. `/api/pos/sync` PRINT_JOB_CREATED 寫入**從不寫 `store_name`**（contentPatch/insert 都冇；連 `kind`/`payment_method`/`total`/`copies`/`ttl`/`printer` jsonb 都從不寫——0020 加畀 Hub 嘅欄寫入端一直冇填）
2. claim RPC `returning j.*` → Hub 收 `"store_name": null`（JSON null）
3. `JobRunner.kt:126` `row.optString("store_name")` — **org.json 對 JSON null 回字面字串 "null"**（key 唔存在先回 ""）→ `.takeIf { isNotBlank() }` 擋唔住
4. 冇 template 嘅 job（例 shift-page:213 交班單重打）行 fallback `renderKitchenTicket` → 第一行印 "null"、第二行【廚房單】

同類地雷：`PrintDtos.parseContent` optString 同款；`pos-app.tsx:2136/2242/2247` `bootstrap.storeName` 未設防（冇 `?? "門店"`）。

### 問題二：重開誤印舊單
- Hub **零本地快取**（HubService 只 claim；HubHttpServer 被動無 outbox）→ 重印素材 100% 係雲端 pending rows
- 根因 = 舊版 upsert 把 sent 打返 pending（docs/101 已修**但 web 從未 deploy**，用戶只 rebuild 咗 APK）
- 「有時候」= 只有初次 flush 失敗過、留喺本地 queue 嘅事件先會被重推（online/visibilitychange/30s 觸發）
- 額外發現：0020 嘅 `ttl` 防線（防隔夜舊單出紙）從未被寫入 → 恆 null → 中毒行永不過期

### 修復方案（等用戶確認）
1. 問題一：server 補寫 store_name/kind/payment_method/total/copies + Hub 統一 `isNull()` 防禦 + pos-app 三處加 `?? "門店"`
2. 問題二：deploy web（docs/101）+ SQL 清中毒行（標 failed 唔好標 sent）+ 建單寫 ttl（30 分鐘）
