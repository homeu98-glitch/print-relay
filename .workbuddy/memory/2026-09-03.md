## 18:25 追加：问题一优化（网页见不到 failed）

### 用户反馈
H10 修复后两系统都收到单，但网页打印中心只显示「已发送」，Hub 印失败也看不到 failed。

### 根因
relay 年代本地 `sent` 只代表「成功入云端队列」，**不代表 Hub 真印到**。真正结果由 Hub 经
`POST /api/pos/print-agent/result` 写云端 `pos_print_jobs.status`（sent/failed + last_error，见 result/route.ts:50-63），
但网页 print-center 从没读回本地。UI 的 failed + lastError 显示位（print-center.tsx:733-751）早写好，只差回填。

### 改动（2 文件）+ 整体 tsc --noEmit 零错误
1. **新增** `src/app/api/pos/print-jobs/status/route.ts`：GET，按 store_id 返 `pos_print_jobs`
   `status IN ('sent','failed')` 的 `{id,status,lastError}`，最多 200 行。故意不返 pending/claimed（防向下覆写）。
2. **print-center.tsx**：加 `import { resolveStoreId } from "@/lib/pos/sync-flush"`
3. **print-center.tsx**：加 `syncCloudPrintOutcomes()` —— 拉端点到本地，用 `job.id` 对碰
   （云端 id = 本地 id，见 sync/route.ts:312,317）；`failed` 覆盖一切带 lastError；`sent` 只升不降；有变才 persist。
4. **print-center.tsx**：加 `useEffect` 轮询（每 8 秒 + 载入即拉一次，卸载清 interval）。

### 设计决策
- 轮询不用 Realtime（收银机网不稳，长连接要写重连，性价比低）；最多慢 8 秒见结果，失败提示场景可接受。
- 只做「失败回填」，不做全套状态机（打印中/已打印），改动最小不碰 types 全场。
- 覆写方向：云只可「向上」覆写本地（failed 覆写一切、sent 只升不降），绝不向下（云 pending 不会漏出来）。

### 验证步骤（deploy 后）
断打印机电源 → 落单 → 等 8-15s → 失败 tab 应见红 badge + 失败原因。复原计划应维持「已发送」。
SQL 查 `select id,status,last_error from pos_print_jobs where status='failed'`。
